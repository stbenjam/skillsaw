# Threat Model: skillsaw

## 1. System context

skillsaw is a CLI linter and autofixer for agentic contextual building
blocks — CLAUDE.md files, plugin manifests, skill definitions, hooks,
MCP configs, and similar artifacts that instruct AI coding assistants.
It is distributed as a Python package on PyPI and runs as a local
developer tool or in CI pipelines (GitHub Actions). It has no network
listeners and no daemon mode.

skillsaw reads files from a target repository, parses them (Markdown,
YAML, JSON, and JSONC), evaluates them against 91 built-in lint rules,
and reports violations. It also validates some metadata against bundled
JSON Schemas. It can automatically fix violations via deterministic
rewrites. A GitHub Action mode posts lint results as PR review comments.
`skillsaw feedback` creates a local diagnostic ZIP but never uploads it.
skillsaw makes no network calls of its own; non-deterministic fixes are
delegated to external coding agents (via the `skillsaw-fix` skill), which
are outside skillsaw's trust boundary.

**Key assumptions:**

- The operator who invokes `skillsaw` controls the target repository.
  In CI, the repository content comes from a pull request and is
  potentially adversary-controlled.
- Config may be discovered in the target repository or one of its parent
  directories, or explicitly selected elsewhere by the operator. Its trust
  level is not necessarily the target repository's.
- Custom-rule paths may be absolute or relative to that config. Loading one
  executes unsandboxed Python by design, so the operator must trust it.
- Dependencies (PyYAML, ruamel.yaml, markdown-it-py, jsonschema) are
  sourced from PyPI. We delegate parsing and schema-validation correctness
  to those libraries.

## 2. Assets

| asset | description | sensitivity |
|---|---|---|
| developer_workstation | Local filesystem of the operator running skillsaw | critical |
| repository_files | Files in the target repo that skillsaw reads and may modify | high |
| ci_gate_integrity | Correctness of the pass/fail exit code in CI pipelines | high |
| pypi_package | The published skillsaw package on PyPI | critical |
| github_token | `GITHUB_TOKEN` used by the review Action to post PR comments | high |
| agent_workflow_tokens | Write-scoped GitHub and coding-agent credentials used by maintenance workflows | critical |
| published_docs | Markdown/HTML pages generated by `skillsaw docs` and published (project sites, catalog indexes) | medium |
| feedback_bundle_contents | Local diagnostic ZIP created for a bug report; it can contain lint output and files the operator explicitly selected | high |

## 4. Threats

| id | threat | actor | surface | asset | impact | likelihood | status | controls | evidence |
|---|---|---|---|---|---|---|---|---|---|
| T1 | Arbitrary code execution via custom rules: a malicious `.skillsaw.yaml` points `custom-rules` at a Python file containing attacker code, which is loaded with `exec_module` | remote_unauth | custom_rule_files | developer_workstation | critical | possible | partially_mitigated | `lint`, `fix`, `baseline`, and `badge` all expose `--no-custom-rules`; the shipped Action defaults it on for pull requests. `feedback` disables custom and plugin rules unless the operator passes `--with-extensions`, and its child runs from a neutral directory with `PYTHONSAFEPATH`. A visible warning is emitted when custom rules load. Custom rules remain intentional trusted code and have no sandbox. | CLI regression tests cover every rule-executing subcommand |
| T4 | CI gate bypass via crafted file content: a PR author triggers parser or rule failures, or exploits baseline/suppression logic, to hide findings | remote_unauth | target_repo_files, skillsaw_yaml_config | ci_gate_integrity | high | rare | partially_mitigated | Rule crashes produce unbaselinable `rule-execution-error` violations and exit nonzero. Tree-build failures are cached and reported fail-closed. Inline suppression and ordinary baselines remain intentional controls whose changes require review. | Crash, recursive-YAML, and unbaselinable synthetic-violation tests |
| T5 | YAML deserialization or parser exhaustion from malformed or recursively nested YAML | remote_unauth | skillsaw_yaml_config, target_repo_files | developer_workstation | medium | very_rare | mitigated | All loaders are safe loaders; `YAMLError` and `RecursionError` are converted into config/frontmatter errors rather than tracebacks. | Recursive YAML regression tests |
| T6 | Path traversal via marketplace/plugin paths or configured instruction paths causes skillsaw to read outside the repository | remote_unauth | marketplace_json_sources, editor_tool_inputs, package_metadata_inputs | repository_files | medium | very_rare | mitigated | Discovery and attachment use `contained_resolve()`, which resolves symlinks before proving containment. Only OpenCode instruction matches resolved inside the repository are attached; normal excludes apply, and remote instruction URLs are not fetched. MCP Registry schemas are bundled and validated with an empty reference registry, so schema URLs are not fetched. | Containment, symlink-escape, OpenCode instruction-path, and MCP Registry schema test suites |
| T8 | Supply chain compromise of skillsaw releases, images, or dependencies | supply_chain | pypi_supply_chain | developer_workstation, pypi_package | critical | rare | partially_mitigated | PyPI uses OIDC trusted publishing and PEP 740 attestations. Container builds use a digest-pinned base, a non-root user, and GitHub provenance attestations. Python dependency hashes and an SBOM remain future work. | Release and Docker workflows |
| T9 | GitHub token exposure or misuse in the review Action | remote_unauth | github_action_env | github_token | high | rare | partially_mitigated | The write-token workflow never executes PR code; PR number/SHA are derived from `workflow_run` and checked against the untrusted artifact. Comment deletion is restricted to the action's own anchored markers, and untrusted Markdown is neutralized. | `test_action_review.py`; review composite metadata checks |
| T11 | Denial of service via resource exhaustion in discovery, parsing, or schema validation | remote_unauth | target_repo_files, package_metadata_inputs | developer_workstation | medium | possible | partially_mitigated | Recursive skill detection tracks resolved directories; HTML comments use a memoized linear scan; recursive YAML is caught; known heavy directories are skipped; MCP Registry diagnostics keep only a bounded schema-error sample. Explicit whole-file size limits remain open. | Symlink fan-out, unterminated-comment, recursive-YAML, and bounded schema-error tests |
| T12 | Suppression/baseline abuse to hide violations in CI: a PR adds `skillsaw-disable` comments or modifies `.skillsaw-baseline.json` to silence real violations while appearing clean | remote_unauth | target_repo_files | ci_gate_integrity | medium | likely | risk_accepted | Suppression and baseline are intentional features for adopting skillsaw incrementally. Stale baseline entries are reported. PR review should catch added suppressions. | None — design-level tradeoff |
| T13 | Config-driven ReDoS: a `.skillsaw.yaml` adds a `content-banned-references` `banned[].pattern` with catastrophic backtracking (e.g. `evilprefix(a+)+$`) plus matching file content, hanging `skillsaw lint` in CI. Survives `--no-custom-rules` (which only gates `.py` custom rules). | remote_unauth | skillsaw_yaml_config, target_repo_files | ci_gate_integrity | high | possible | partially_mitigated | Each config-supplied banned pattern runs under a per-pattern wall-clock budget (`regex-timeout`, default 2s, clamped to 10s) enforced with `SIGALRM`; on timeout the pattern is skipped with a reported violation instead of hanging. Best-effort: the `SIGALRM` timer is a no-op off the main thread and on platforms without `SIGALRM` (e.g. Windows). | `regex-timeout` (this change) |
| T14 | Credential disclosure via lint reports: a manifest or catalog value carrying an embedded credential (a URL with userinfo written into a `source`, `path`, or asset field) is echoed into violation messages, which CI workflows upload as JSON/SARIF artifacts and feed to code-scanning ingestion | remote_unauth | codex_plugin_inputs, marketplace_json_sources | ci_gate_integrity | medium | possible | mitigated | Manifest-derived values that parse as URLs with an authority have their `username`/`password` stripped before interpolation into violation messages, across text, JSON, and SARIF output; `codex-marketplace-json-valid` omits raw registry values entirely. `safe_display()` runs over unbounded manifest values: the display cap is applied before the redaction scan, so an adversarial multi-megabyte value bounds the work as well as the output (see T11) | redaction of URL userinfo in Codex rule messages (v0.18.0) |
| T15 | Stored XSS / Markdown injection through generated documentation (partially mitigated — see accepted risk on author prose): a third-party plugin in an aggregated catalog carries a crafted `homepage`/`repository` URL (`javascript:` scheme, literal or entity-encoded), a name or metadata value with Markdown/HTML control text, or a value that breaks out of the HTML page's inline-script string context — and the payload activates when the generated pages are published | remote_unauth | generated_docs | published_docs | medium | possible | partially_mitigated | `_safe_url()` decodes HTML character references to a fixed point, then enforces a scheme allow-list and percent-encodes parentheses; `_link_dest()` re-encodes `&` at the Markdown link sink so entity text cannot reassemble a scheme at render time; `_safe_markdown_prose()` neutralizes inline, reference, image, and autolink destinations with unsafe schemes while preserving description prose; `_table_cell()` folds newlines and escapes Markdown link/table delimiters in every metadata scalar the Markdown renderer interpolates; `escAttr`/`escJsAttr` escape HTML/JS sinks, and `_unique_filenames` prevents page-name collisions. **Accepted risk:** `description` fields and command `synopsis`/`body` content render as author prose by design; command bodies pass through verbatim and a synopsis can terminate its fixed code fence, so publishers aggregating third-party catalogs should use a sanitizing pipeline. | `_safe_url` + `_safe_markdown_prose` + `_table_cell` + `escJsAttr` + `_unique_filenames`; hostile-link and hostile-metadata tests |
| T16 | Predictable generated artifact paths or autofix targets are symlinked to overwrite files outside the repository | remote_unauth | target_repo_files, feedback_bundle_inputs | developer_workstation, repository_files | high | possible | partially_mitigated | Baseline, badge/card, generated-doc files, and repository-local feedback bundles use symlink-refusing atomic replacement. On platforms with descriptor-relative filesystem operations, autofix writes and renames pin repository parent directories without following symlinks at the write boundary. Other platforms validate containment and reject symlinked parents and endpoints immediately before the native rename, but cannot eliminate path-swap races without equivalent OS primitives. | Symlink-output, feedback-output, and autofix regression tests |
| T17 | Prompt injection or code execution in privileged autonomous maintenance workflows misuses write-scoped tokens | remote_unauth | agent_workflow_input | agent_workflow_tokens, repository_files | critical | possible | partially_mitigated | Privileged maintenance agents have shell/network access and a write-scoped token under automatic permission mode; this is not a tool-isolation boundary. Runbooks instruct agents to trust only enumerated reviewers, avoid executing PR code, source review inputs from GitHub APIs, and verify Git and CI state after execution; edited issue bodies require fresh collaborator approval. Repository rulesets must still require PR review/checks and protect release tags. | Agent workflow definitions and runbooks |
| T18 | A feedback bundle discloses repository content, credentials, local paths, or terminal control sequences when the operator shares it | remote_unauth, local_user | feedback_bundle_inputs | repository_files, developer_workstation, feedback_bundle_contents | high | possible | partially_mitigated | `feedback` creates a local ZIP and never uploads it. `--include` accepts only safe, contained UTF-8 files; an explicit config may be outside the repository. Both selections' named and resolved paths are checked against credential-shaped filenames and supported root/ancestor ignore files. Auto-discovered config is never bundled; if it is ignored, its diagnostics are withheld too. Extensions are disabled by default; the child has a 120-second timeout. Diagnostics have terminal controls and common local paths removed. Repository-local bundles use private atomic writes, refuse overwrite and symlink escapes, and carry a manifest and checksum. **Residual:** selected files are included without secret filtering, diagnostics may contain repository-derived text, and ignore matching is a conservative refusal guard rather than proof of sanitation. The operator must inspect the ZIP before sharing it. | `tests/test_feedback.py`; CLI review-before-sharing notice |
| T19 | Repo-controlled regex compilation: a Muse Code or Grok Build hooks file's `matcher` field is defined within the repository, and `muse-hooks-valid` / `grok-hooks-valid` compile it as a regular expression during validation | remote_unauth | editor_tool_inputs | ci_gate_integrity | low | possible | mitigated | The repo-controlled pattern is compiled for syntax validation only and is never used to match input text, so it cannot drive match-time backtracking (ReDoS). It is, however, *scanned*: before compiling, the shared `rust_matcher_error()` helper rewrites Rust-only atoms into their Python spellings, running a few of skillsaw's own bounded patterns over the matcher and walking it at most twice. Four things bound that work — matchers longer than 1,000 characters are not compile-checked at all (and report nothing, since neither host imposes a length limit, so length is not a defect); the Unicode-class pattern's braced name is capped at 64 characters; the class-set-operator pass is a single linear walk that consumes escapes whole and never backtracks; and `re.compile` is wrapped in an exception guard (`re.error`, `RecursionError`, `OverflowError`) so a pathological pattern produces a violation rather than interrupting the lint run. | `muse-hooks-valid`, `grok-hooks-valid` (`rust_matcher_error()` in `rules/builtin/utils.py`) |

Retired threat IDs T2, T3, T7, and T10 covered the built-in LLM fix path
(`fix --llm`, LLM tool-call dispatch, and `--apply-patch`), which was
removed along with the litellm dependency. Non-deterministic fixes now
happen inside the operator's coding agent, whose own sandboxing and
review workflow govern that risk.

## 5. Deprioritized

| threat | reason |
|---|---|
| Malicious operator running skillsaw with `--path /` to read arbitrary files | The operator already has filesystem access; skillsaw does not escalate privilege. Actor is `local_admin`, which is outside the threat model for a CLI tool that runs as the invoking user. |
| Bugs in Python's `argparse` or `pathlib` standard library | Upstream responsibility; filed against CPython. |
| Prompt injection against a coding agent fixing violations via the `skillsaw-fix` skill | The agent runs under the operator's harness (Claude Code, Cursor, etc.), whose permission model and review workflow govern file writes. skillsaw only supplies lint output and `skillsaw explain` guidance. |
| Side-channel timing attacks on YAML parsing | No security-sensitive branching depends on YAML parse timing. |
| Memory-safety bugs in CPython or PyYAML C extensions | Upstream responsibility; skillsaw does not use `ctypes` or native extensions directly. |
