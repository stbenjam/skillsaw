# Step 7: Set up CI

Ask which CI system the repository uses. Apply only the selected section.

## GitHub Actions

Resolve current commit SHAs before writing workflows:

```console
git ls-remote --tags https://github.com/actions/checkout.git v5
git ls-remote --tags https://github.com/stbenjam/skillsaw.git v0
```

Create `.github/workflows/lint.yml`, using those SHAs with trailing version
comments:

```yaml
name: Lint

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  skillsaw:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<CHECKOUT_SHA> # v5
        with:
          persist-credentials: false
      - uses: stbenjam/skillsaw@<SKILLSAW_SHA> # v0
        with:
          strict: true
```

Offer PR review comments. If accepted, add
`.github/workflows/lint-review.yml`:

```yaml
name: Lint Review

on:
  workflow_run:
    workflows: ["Lint"]
    types: [completed]

jobs:
  review:
    if: github.event.workflow_run.event == 'pull_request'
    runs-on: ubuntu-latest
    permissions:
      pull-requests: write
    steps:
      - uses: stbenjam/skillsaw/review@<SKILLSAW_SHA> # v0
```

External URL availability is outside skillsaw's deterministic lint scope. Offer
a weekly check with the dedicated
[Lychee Action](https://github.com/lycheeverse/lychee-action). If accepted,
resolve its current v2 SHA:

```console
git ls-remote --tags https://github.com/lycheeverse/lychee-action.git v2
```

Create `.github/workflows/link-check.yml` with the resolved checkout and Lychee
SHAs:

```yaml
name: Link Check

on:
  workflow_dispatch:
  schedule:
    - cron: '17 7 * * 1'

permissions:
  contents: read

concurrency:
  group: link-check
  cancel-in-progress: false

jobs:
  links:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@<CHECKOUT_SHA> # v5
        with:
          persist-credentials: false
      - uses: lycheeverse/lychee-action@<LYCHEE_SHA> # v2
        with:
          args: >-
            --no-progress
            --exclude-all-private
            --root-dir .
            './**/*.md'
          fail: true
          jobSummary: true
```

Keep the link check scheduled rather than merge-blocking: remote availability,
rate limits, and bot defenses are outside the repository's control.

## GitLab CI

Add a `skillsaw` job to `.gitlab-ci.yml` so violations appear in merge-request
Code Quality results:

```yaml
skillsaw:
  image: ghcr.io/stbenjam/skillsaw:latest
  stage: test
  script:
    - skillsaw --strict --output gitlab:gl-code-quality.json
  artifacts:
    reports:
      codequality: gl-code-quality.json
```

## No CI

If the user declines CI, leave it unchanged and point them to the
[CI documentation](https://skillsaw.org/ci/).

Record the selected setup, then return to the router and read Step 8.
